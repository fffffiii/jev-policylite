# 四张照片一次输入：逐图定位与耗时实验 v1

运行日期：2026-09-23。硬件：NVIDIA RTX 3090，GPU 1。基础检查点：`public-pilot-multihead`（Qwen3.5-0.8B + 已训练 LoRA）。本实验只训练新的逐图检测头；视觉编码器、语言主干、LoRA 和原有审核头全部冻结。

## 问题与方法

给四张图和同一条审核规则，输出第 1、2、3、4 张图各自的违规分数。四张图的位置顺序固定为左上、右上、左下、右下。比较六种做法：

| 方法 | 前向计算 | 逐图读出 |
| --- | --- | --- |
| 逐张串行 | 四次单图前向 | 原二元违规头 |
| 单图 batch=4 | 一次批量前向，四条独立序列 | 原二元违规头 |
| 原生四图，共享末 token | 一条含四个 image 项的序列，一次前向 | 四个位置头读取同一个末 token |
| 原生四图，局部读出 | 同上 | 四个位置头分别读取对应 `vision_end` 的隐藏状态 |
| 原生四图，共享局部头 | 同上 | 同一个头依次读取四个 `vision_end` 状态 |
| 实时 2×2 拼图 | 四张图拼成一张，单图前向 | 四个位置头读取末 token |

四个独立位置头合计 **12,292** 个参数；共享局部头 **3,073** 个参数。训练先缓存冻结特征，再只优化这些小头。原生四图和单图基线的每张图片都限制为 **50,176 像素**；拼图为 448×448、整图上限 **200,704 像素**。

训练、验证、测试分别由源清单的对应划分构造 **480 / 120 / 200** 组，每组四张不同原图。两条政策各占一半；四种场景为全安全、恰好一张违规、两张违规、全违规。逐图标签直接来自每张源图在该政策下的二元标签，整图标签为四个标签的 OR。2026-09-26 核查确认：三份组合分别覆盖 **1,127 / 234 / 426 张不同原图**，原图组不跨划分；800 个测试位置标签来自 426 张原图，不能按 800 张独立原图计算置信区间。

局部读出仍属于因果序列：第 2–4 张图的表征可以包含前面图片的信息，第 1 张图不能读取后面的图片。它与 batch=4 的独立序列不同；同时，两种输入的提示结构也不同，结果不能单独归因于检测头的数量。

## 独立测试集结果

200 组、800 个逐图判断。所有方法使用 **0.5** 阈值；没有在测试集上校准阈值。

| 方法 | 逐图准确率 | 四张全对 | 单张违规时最高分位置正确 | 平均耗时/组 | P50 | P95 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 逐张串行 | **90.12%** | **65.0%** | **94.0%** | 537.47 ms | 539.93 ms | 544.34 ms |
| 单图 batch=4 | 89.75% | 64.0% | 94.0% | 163.79 ms | 165.73 ms | 169.85 ms |
| 原生四图，共享末 token | 84.88% | 55.0% | 86.0% | **153.08 ms** | 154.73 ms | 157.76 ms |
| 原生四图，局部读出 | 87.50% | 60.0% | 86.0% | 154.64 ms | 154.89 ms | 157.47 ms |
| 原生四图，共享局部头 | 87.12% | 58.5% | 90.0% | 153.97 ms | 154.12 ms | 157.48 ms |
| 实时 2×2 拼图 | 80.75% | 50.0% | 72.0% | 182.59 ms | 181.02 ms | 195.44 ms |

局部读出比同样一次前向的共享末 token 方案提高 **2.62 个百分点**的逐图准确率，耗时基本相同。这与共享末 token 难以保留四张图各自证据的假设相符，但单次试验不能独立证明错误的成因。

与更实际的 **batch=4** 基线相比，局部读出平均每组只快约 **9.15 ms（5.6%）**，逐图准确率低 **2.25 个百分点**，四张全对率低 **4 个百分点**。与逐张串行相比则快约 **3.47 倍**。因此当前结果不支持把“单次四图定位”宣传为准确率不变的高速替代；如果更在意正确率，应优先使用单图 batch=4。预制拼图的前向约 135 ms，但实际把四张图片临时拼接、编码为 JPEG 后，总耗时升至表中的 183 ms 左右，且定位准确率最低。

## 计时边界与限制

六种方法在相同 200 组测试样本、同一进程、同一 GPU 上交替测量，并分别预热对应输入形态。计时包含读取原图、预处理、主干前向和检测头；实时拼图还包含缩放、排版和 JPEG 编码。计时**不包含**模型加载、HTTP 上传与返回、请求排队，也不代表手机或普通电脑上的离线速度。训练特征抽取时的 CUDA 峰值分配约为 **1.7 GiB**，它不是整个服务的显存占用。

这是 2026-09-23 的历史运行，不能与 2026-09-26 的跨系统实验直接拼成同一次计时。旧运行没有保存全部六种方法的逐组计时和预测，所以无法追溯计算该运行的置信区间；更新后的脚本会额外保存 `comparison_samples.jsonl`。旧数据的组合 ID 在不同划分目录中复用，原评测按目录读取，因此没有造成原图泄漏；新生成器已把 split 纳入 ID。

标签来自公开试训原图，不是人工重新审核四图组合；源图可能在同一测试划分的不同组合中重复。模型主要针对这两条性内容政策，不能据此推断其他审核任务的效果。所有逐图分数为未经单独校准的 sigmoid 输出。冻结特征若丢失关键视觉细节，后接小头无法恢复。
